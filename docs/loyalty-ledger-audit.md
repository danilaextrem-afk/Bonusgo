# QRonus — безопасная сверка бонусных балансов

## Назначение

Внутренняя серверная функция `auditCompanyLedger(companyId)` в
`src/server/loyalty/ledger-audit.ts` сопоставляет хранимый баланс каждой
карты компании с суммой `transactions.amount` по этой карте. Дополнительно
проверяет, нет ли транзакций, указывающих на другую компанию.

Функция только **читает** PostgreSQL. Она не корректирует баланс, не создаёт
начисления и не отправляет уведомления. Отчёт не содержит имён, email или
QR-токенов клиентов; только ID карт и числовые значения. Метод **не привязан к публичному API**. Закрытая страница `/admin/ledger`
доступна только пользователям с ролью `ADMIN` в базе (настройки `ADMIN_EMAILS`
недостаточно). Доступ дополнительно проверяется серверным методом
`runAdminLedgerAudit`, который ограничивает запросы 5/мин на администратора и
записывает в журнал только идентификатор компании, счётчики и идентификатор
администратора. Никакие QR-токены и личные данные клиентов не регистрируются.

## Правила эксплуатации

1. Использовать только через защищённый сервис `runAdminLedgerAudit` из
   закрытой админ-панели; прямой вызов `auditCompanyLedger` нельзя
   предоставлять пользовательским API без проверки полномочий.
2. При `discrepancies.length > 0` сохранить отчёт для расследования и
   проверить соответствующие транзакции и изменения базы. Не исправлять
   данные автоматически и не менять баланс напрямую.
3. При ошибке чтения или превышении диапазона безопасных целых чисел считать
   результат неопределённым. Не утверждать, что сверка успешно завершилась.
4. Сверка относится только к **бонусным картам**, а не к платёжным счетам,
   реальным денежным операциям или инвентаризации заведений.

## Ограничение объёма

Доступны два режима в закрытой странице `/admin/ledger`:

- **Стандартный** — до 10 000 бонусных карт одним запросом.
- **Пакетный** — до 50 000 карт, по 500 карт за запрос внутри одной
  `REPEATABLE READ READ ONLY` транзакции PostgreSQL. Постраничная выборка
  по ID исключает хранение всех карт в памяти. Отчёт считает **все**
  расхождения, но сохраняет не более 50 ID карт-примеров.

Оба режима завершаются ошибкой `AUDIT_TOO_LARGE` (413) при превышении
порога; **неполный результат не выдаётся как успешный**. Более масштабная
сверка требует отдельной ограниченной фоновой процедуры. Для пакетной
проверки все страницы читаются из одного снимка базы данных, чтобы
одновременные начисления не искажали итог. Никаких корректировок
баланса, платежей и реальных списаний код не выполняет.

## Регрессионные проверки

`tests/integration/loyalty.test.ts` проверяет:

- Нулевую компанию и нормальную историю «начисление → списание».
- Обнаружение несогласованного баланса, без исправления данных.
- Обнаружение транзакции, ошибочно отнесённой к чужой компании.
- Конкурентные начисления, списания и повторное сканирование QR.
- Пакетную сверку через несколько страниц, точный счётчик расхождений
  и ограничение количества возвращаемых примеров.

Запуск в GitHub Actions: `npm run lint`, `npm run typecheck`,
`npm test`, `npm run build`, `npm run test:e2e`. Требуется
изолированная тестовая PostgreSQL. Запуск CI сам по себе не проверяет
реальные данные облачной базы или деплой Render.
