# QRonus — безопасная сверка бонусных балансов

## Назначение

Внутренняя серверная функция `auditCompanyLedger(companyId)` в
`src/server/loyalty/ledger-audit.ts` сопоставляет хранимый баланс каждой
карты компании с суммой `transactions.amount` по этой карте. Дополнительно
проверяет, нет ли транзакций, указывающих на другую компанию.

Функция только **читает** PostgreSQL. Она не корректирует баланс, не создаёт
начисления и не отправляет уведомления. Отчёт не содержит имён, email или
QR-токенов клиентов; только ID карт и числовые значения. Метод **не привязан
к публичному маршруту**. Перед интеграцией в закрытую админ-панель необходимо
добавить серверную авторизацию администратора, ограничение частоты и аудит вызовов.

## Правила эксплуатации

1. Вызывать только внутри доверенного серверного процесса, с `companyId`,
   подтверждённым серверной проверкой прав.
2. При `discrepancies.length > 0` сохранить отчёт для расследования и
   проверить соответствующие транзакции и изменения базы. Не исправлять
   данные автоматически и не менять баланс напрямую.
3. При ошибке чтения или превышении диапазона безопасных целых чисел считать
   результат неопределённым. Не утверждать, что сверка успешно завершилась.
4. Сверка относится только к **бонусным картам**, а не к платёжным счетам,
   реальным денежным операциям или инвентаризации заведений.

## Регрессионные проверки

`tests/integration/loyalty.test.ts` проверяет:

- Нулевую компанию и нормальную историю «начисление → списание».
- Обнаружение несогласованного баланса, без исправления данных.
- Обнаружение транзакции, ошибочно отнесённой к чужой компании.
- Конкурентные начисления, списания и повторное сканирование QR.

Запуск в GitHub Actions: `npm run lint`, `npm run typecheck`,
`npm test`, `npm run build`, `npm run test:e2e`. Требуется
изолированная тестовая PostgreSQL. Запуск CI сам по себе не проверяет
реальные данные облачной базы или деплой Render.
