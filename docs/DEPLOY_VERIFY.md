# QRonus: проверка фактически развёрнутого коммита на Render

## Зачем

Зелёный GitHub Actions означает, что исходники успешно прошли проверки,
но **не означает**, что Render уже развернул этот же коммит.

Для проверки версии используйте отдельный публичный
`GET /api/version`. Он не выполняет запросы к PostgreSQL и не запускает
фоновые задачи. Пример ответа:

```json
{ "revision": "a7b8c9d01234" }
```

`GET /api/health` по-прежнему возвращает `ok`, `time` и `revision`, но
также запускает best-effort housekeeping: для проверки версии его
использовать не следует.

Поле `revision` равно первым 12 символам проверенной переменной
`RENDER_GIT_COMMIT`. Если переменная недоступна или имеет неверный формат,
возвращается `null`, а **не** выдуманный коммит. Обработчик выставляет
`Cache-Control: no-store, max-age=0` и `X-Robots-Tag: noindex, nofollow`.
Никакие ключи и остальные переменные окружения не передаются клиенту.

## Безопасная процедура

1. Найдите последний успешный коммит в
   [GitHub Actions](https://github.com/danilaextrem-afk/Bonusgo/actions).
2. Откройте `https://qronus.onrender.com/api/version` в браузере или
   выполните `curl -i https://qronus.onrender.com/api/version`.
3. Сравните поле `revision` с первыми 12 символами SHA успешного коммита.
4. Если не совпадает, проверьте в **своём** Render Dashboard ветку `main`,
   последние Deploys/Events, build/start commands и режим Auto Deploy.
   Render не обязан разворачивать каждый push, если автодеплой отключён,
   настроена другая ветка или деплой завершился ошибкой.
5. Если `revision: null`, проверить SHA этим методом нельзя: проверьте
   переменную `RENDER_GIT_COMMIT` и способ развертывания через панель Render.
6. Если сам URL не отвечает, сначала проверить DNS, sleep/пробуждение
   бесплатного инстанса, логи приложения и работоспособность базы.
   Ошибка DNS одного клиента ещё не означает глобальный отказ сайта.

Никогда не делитесь токенами Render, секретами, строкой подключения к БД
или deploy-hook URL в переписке. Не запускайте платные услуги и не включайте
реальные платежи для выполнения этого шага.

Важно: `/api/version` предназначен для сверки SHA **без побочных эффектов**.
В отличие от него, `/api/health` запускает best-effort housekeeping через
`runDueJobs()`; для диагностики публикации используйте `/api/version`.

## Автотесты

`tests/unit/deployment-revision.test.ts` проверяет формат и отсутствие
утечки недоверенного значения. `tests/e2e/health.spec.ts` проверяет
оба ответа локально запущенного приложения, запрет кеширования,
ограниченный набор полей и стабильность SHA при повторных запросах. Эти тесты не подменяют проверку
`qronus.onrender.com` после деплоя.
